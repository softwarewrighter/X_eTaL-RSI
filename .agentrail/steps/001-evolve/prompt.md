The Evolve library (ev:): the improvement loop as protected mechanism (plan A1, A8). An optimizer is a parameter vector (shortest and longest tool, tools kept, the journal window of recent tasks learned from, how often to revise), interpreted by fixed library code: every period batches it synthesizes a candidate from the recent journal (Policy's s_ynthesize), reviews it with the Guardian (held-out = the most recent batch), records it in the append-only history, and runs the next batch with whatever policy is running; it reports per batch the production, learning and review tokens, the verdicts and the versions. Doc examples, basics, types, a demo. Experiment 03 (policy evolution): a stream of batches whose recipe shifts twice; groups A fixed, C tools learned once, D evolving guarded, D evolving unguarded; the timeline of accepted and rejected revisions and what each cost, claims checked, README with results and limits.
